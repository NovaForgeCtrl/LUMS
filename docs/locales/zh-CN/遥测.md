# LUMS CPU、内存和网络遥测

## 概述

可选的 LUMS 遥测代理会从受管理的 Linux 系统收集 CPU 使用率、内存使用率、网络计数器以及有限的主机快照，并将测量结果发送到 LUMS 服务器。

服务器会存储遥测样本，并提供经过身份验证的历史记录 API，供客户端遥测仪表板使用。

遥测与现有 LUMS reporting Agent 和 Watcher 分开。它不会取代这两个组件，也不会执行软件包更新。

## 组件

| 组件 | 职责 |
| --- | --- |
| `agent/telemetry.py` | 收集 CPU、内存、主机、网络、传感器、服务和容器指标 |
| `agent/lums-telemetry.service` | 以受限的 systemd 服务运行遥测代理 |
| `agent/lums-telemetry.timer` | 定期安排遥测收集 |
| `server/app.py` | 验证提交请求、校验指标并存储样本 |
| `server/static/telemetry.js` | 显示设备群概览、历史图表和环形仪表 |

## 测量数据

每个样本都包含以下必需字段：

- `cpu_percent`：CPU 使用率，范围为 0 到 100。
- `memory_percent`：内存使用率，范围为 0 到 100。
- `memory_total_bytes`：检测到的内存总量（字节）。
- `memory_available_bytes`：可用内存量（字节）。

1.1.0 及更高版本的代理还会发送以下两个可选的累计计数器：

- `network_rx_bytes`：自启动以来接收的字节数，对所有非环回接口求和。
- `network_tx_bytes`：自启动以来发送的字节数，对所有非环回接口求和。

必须同时发送这两个计数器，且值必须是非负整数。未提供这两个字段的旧版代理仍可正常工作，但仪表板不会显示该客户端的网络数据。服务器会存储原始计数器，并在请求数据时根据连续样本计算每秒字节数。对于第一个样本、计数器重置之后（例如系统重启后），或者两个样本间隔超过五分钟的情况，不会显示速率。

1.2.0 及更高版本的代理还会报告有限的系统快照：

- 负载平均值、运行时间、操作系统、内核和根文件系统使用情况；
- 每个网络接口的链路状态、字节计数器、错误和丢弃数；
- 已配置的 DNS 服务器，以及尽力检测的网关、DNS 和互联网可达性；
- 内核公开时提供的温度和风扇读数；
- 所选 systemd 服务的状态、运行时间和重启次数；在本地工具与权限允许只读检查时，也包括 Docker 和 Podman 容器名称及标准化状态。
- 每个遥测样本时的磁盘使用率，用于历史图表和阈值事件评估。

1.3.0 及更高版本的代理还会报告有限的运行事件摘要：SSH 登录失败次数和时间戳、近期 journal 警告和错误计数、登录／注销时间戳，以及近期启动期间 journal 的首末时间戳。不会发送原始 journal 消息、用户名或来源地址。每次 journal 查询最多匹配 500 条记录；仪表板会将计数 500 标记为 `500+`。启动历史最多保留 10 次启动，登录／注销历史最多保留 20 个事件。

服务器会根据连续样本计算每个接口的吞吐量。服务、容器、温度、风扇和事件详情仅存储最新快照，不会重复写入每个历史样本。操作系统未公开或未授权访问的可选指标会显示为不可用。代理不会启动、停止或修改服务和容器。代理服务不会获得 Docker 套接字访问权限；只有运行环境原本就允许服务账户检查容器时，容器详情才可用。

遥测 systemd 单元属于 `systemd-journal` 组，以便只读访问 journal。这会授予其读取系统日志的权限，但代理仅发送上述有限摘要。默认服务允许列表包含 LUMS、Docker 和 SSH 单元。可在代理环境文件中设置逗号分隔的 `LUMS_MONITORED_SERVICES` 值来覆盖该列表；只接受有效的 `.service` 单元名称。

如果可用，网关可达性检查会发送一个数据包的 ping；DNS 可达性检查会执行一次简短的 `getent` 查询；互联网可达性检查会尝试与 `1.1.1.1:443` 建立短暂的 TCP 连接。这些检查仅作为参考指标，有时反映的是防火墙策略，而非服务中断。

样本时间戳由服务器分配，无效负载会被拒绝。

更新服务器后，请运行一次数据库迁移（`python3 server/security_migration.py`），以创建网络列、最新系统状态表、仪表板设置和事件历史。还需更新每个客户端上的代理以开始报告新指标。若要监控 LUMS 服务器本身，请将其注册为客户端，并在该主机上安装和配置遥测代理。

## 安全与隐私

遥测端点要求使用已配置的 LUMS 客户端令牌进行客户端身份验证。

代理连接远程服务器时使用 HTTPS。仅允许对 `localhost`、`127.0.0.1` 和 `::1` 使用明文 HTTP。连接远程服务器必须使用 HTTPS。可选配置 CA 文件以验证证书。

代理不会在 JSON 负载中包含客户端令牌，也不会记录该令牌。systemd 服务采用受限的执行环境；收集本文档所述指标不需要 root 权限。

遥测数据包含系统资源和运行元数据，不包含软件包更新或任意命令输出。接口地址、DNS 服务器、服务名称和容器名称可能属于敏感基础设施信息；仪表板和 API 仍受 `clients.view` 权限保护。

## 数据保留

服务器在处理新的遥测提交时，会删除超过七天的遥测样本。

经过身份验证的历史记录端点接受 1 到 168 小时的时间范围。访问需要适当的客户端查看权限。大型结果集可能会降采样到最多 1,000 个样本。

`/health` 仪表板提供 1 小时、24 小时和 7 天的历史范围，并每五秒刷新显示的数据。对于选定的客户端，仪表板显示 CPU、内存、磁盘使用率和网络总量历史，以及最新的磁盘、负载、运行时间、内核、操作系统、接口、连接状态、传感器、服务和容器详情。仪表板还显示设备群概览，可按状态、遥测过期或高负载筛选，并支持搜索、排序和查看各客户端详情。CPU 和内存可显示为折线图、面积图或当前值环形仪表；浏览器会记住选择的显示方式。网络流量显示为下载和上传速率。超过两分钟的遥测会标记为过期。设备群概览使用 `/api/telemetry/overview` 端点，该端点要求客户端查看权限。历史记录请求限制为 1–168 小时，并可能降采样至最多 1,000 个样本。systemd timer 配置为每五秒运行一次单次代理任务；实际样本频率取决于服务完成时间和网络可用性。仪表板还显示近期 SSH 失败、journal 警告／错误计数、登录／注销历史和启动历史。阈值警告使用已登录用户配置的 CPU、RAM 和磁盘上限。每次 journal 查询最多统计 500 条匹配记录。最后一次成功创建备份的时间取自服务器审计日志；这并不代表已进行恢复测试。

健康仪表板采用固定布局。每位用户可单独设置 CPU、RAM 和磁盘阈值（50% 到 99%，默认值为 90%）。阈值越界和超过两分钟的遥测中断会显示在事件历史中。阈值警报根据保留的样本推导，并使用当前登录用户的阈值；服务状态变化和新报告的 SSH 失败时间戳会在数据接收时记录。事件最多保留七天，事件端点最多返回 500 条记录。

可为所选客户端和时间范围导出 CSV 和 JSON。历史下载包括该范围内保留的所有样本；图表仍限制为最多 1,000 个点。导出需要 `clients.view` 权限，且浏览器不会缓存导出内容。

Wazuh 和 Suricata 可作为可选的用户级状态行显示。这些行只显示已配置的 systemd 服务状态；LUMS 不会连接其 API 或收集其警报。若要报告某项服务，请将其已安装单元（例如 `wazuh-agent.service`、`wazuh-manager.service` 或 `suricata.service`）添加到代理的 `LUMS_MONITORED_SERVICES` 允许列表。LUMS 不需要或存储任何集成凭据。

## 配置

遥测代理使用 `LUMS_BASE`、`LUMS_TOKEN` 和可选的 `LUMS_CA_FILE` 环境变量。连接远程服务器必须使用 HTTPS。安装和配置说明请参阅[安装指南](安装与升级.md)。

## 安装与运行

遥测服务与常规 LUMS 客户端分开。在 Debian 上，先更新客户端上的 LUMS 仓库检出，然后从其根目录运行 `sudo bash scripts/install-telemetry-agent.sh`。安装程序会检查 `/etc/default/lums-agent` 是否定义了 `LUMS_BASE` 和 `LUMS_TOKEN`，安装当前采集器和 systemd 单元，启用 timer 并发送测试样本。它不会显示令牌。

使用 `systemctl status lums-telemetry.timer` 和 `systemctl status lums-telemetry.service` 检查 timer 与服务。使用 `journalctl -u lums-telemetry.service -n 30 --no-pager` 查看近期服务日志。定时运行之间，单次服务处于非活动状态不一定代表错误；同时检查 timer 和近期日志。

`/monitoring` 页面会区分没有样本、只有基本遥测但没有详细快照，以及快照已过期的情况，并显示这些客户端侧检查结果。排查问题时不要粘贴或分享令牌。

## 故障排除

- **未显示样本：** 检查服务器 URL、客户端令牌和身份验证。
- **TLS 错误：** 检查服务器证书和已配置的 CA 文件。
- **服务失败：** 检查服务 journal。
- **缺少历史记录：** 检查客户端查看权限和请求的时间范围（1–168 小时）。

有关仪表板状态阈值及其备份存储指示器的限制，请参阅[LUMS 健康仪表板](系统健康仪表板.md)。一般指导请参阅[安装指南](安装与升级.md)和[故障排除指南](故障排查.md)。英文原文：[Telemetry](../../../telemetry.md)。
