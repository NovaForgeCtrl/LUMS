# 恢复 LUMS 数据库备份

本指南介绍如何在 Docker 部署中恢复 `.db` 或 `.db.gz` 备份。恢复操作会替换当前活动数据库。请谨慎操作，并在 Debian 主机上执行这些步骤。

## 先决条件

你需要准备：

* 备份存储的主机路径，例如 `/mnt/lums-nas-backups`
* 如果使用了 LUMS 备份界面中的子目录，则需要所选子目录
* 备份文件名
* 数据库卷名称，通常为 `lums-data`
* 一次性恢复容器所用的 LUMS 镜像

请使用与正在运行的安装相同的镜像版本。可以使用以下命令查看已配置的镜像名称：

```bash
sudo docker inspect lums --format '{{.Config.Image}}'
```

将下方的 `lums:SET-TO-ACTIVE-IMAGE-TAG` 替换为该镜像的准确名称。不要仅仅因为主机上还留有旧镜像标签就使用它。

NAS／文件系统挂载必须可用。恢复前请检查：

```bash
mountpoint /mnt/lums-nas-backups
ls -lh /mnt/lums-nas-backups
```

请将 `/mnt/lums-nas-backups` 调整为实际的主机路径。LUMS 显示的是容器路径；Docker 挂载左侧是主机路径。

## 恢复

根据你的安装设置变量。`BACKUP_FILE` 必须指定备份挂载中的一个文件名。如果使用界面中的子目录，请将其加到路径中，例如 `wochenende/lums-backup-....db.gz`。

```bash
BACKUP_ROOT=/mnt/lums-nas-backups
BACKUP_FILE=lums-backup-DATEINAME.db.gz
LUMS_VOLUME=lums-data
LUMS_IMAGE=lums:SET-TO-ACTIVE-IMAGE-TAG
```

停止 LUMS，并将当前数据库另存为额外的回退副本：

```bash
sudo docker stop lums
sudo docker cp lums:/var/lib/lums/lums.db \
  "/root/lums-before-restore-$(date +%F-%H%M%S).db"
```

使用一次性辅助容器恢复所选备份。脚本会在替换数据库前检查完整性，并将文件所有者恢复为 LUMS 运行时用户：

```bash
sudo docker run --rm \
  --user 0:0 \
  --entrypoint python \
  -v "$LUMS_VOLUME:/var/lib/lums" \
  -v "$BACKUP_ROOT:/backups:ro" \
  "$LUMS_IMAGE" \
  -c '
import gzip
import os
import shutil
import sqlite3
import sys
import tempfile

source_path = sys.argv[1]
database_path = "/var/lib/lums/lums.db"
fd, temporary_path = tempfile.mkstemp(
    prefix=".lums-restore-",
    suffix=".db",
    dir="/var/lib/lums",
)
os.close(fd)
try:
    opener = gzip.open if source_path.endswith(".gz") else open
    with opener(source_path, "rb") as source, open(temporary_path, "wb") as target:
        shutil.copyfileobj(source, target)

    database = sqlite3.connect(temporary_path)
    try:
        result = database.execute("PRAGMA integrity_check").fetchone()
    finally:
        database.close()
    if result is None or result[0] != "ok":
        raise RuntimeError("Backup failed SQLite integrity_check")

    for suffix in ("-wal", "-shm"):
        sidecar = database_path + suffix
        if os.path.exists(sidecar):
            os.unlink(sidecar)
    os.chmod(temporary_path, 0o600)
    os.chown(temporary_path, 10001, 10001)
    os.replace(temporary_path, database_path)
    print("Backup restored and integrity_check passed.")
finally:
    if os.path.exists(temporary_path):
        os.unlink(temporary_path)
' "/backups/$BACKUP_FILE"
```

重新启动 LUMS 并检查迁移和服务：

```bash
sudo docker start lums
sudo docker logs --tail 100 lums
curl -s -o /dev/null -w 'GET /login: %{http_code}\n' \
  http://127.0.0.1:5050/login
```

然后检查登录、用户、客户端和作业。如果恢复的备份早于当前应用程序版本，LUMS 可能会在启动时运行数据库迁移。

## 如果恢复失败

不要让有问题的数据库继续作为生产数据运行。再次停止 LUMS。将 `BACKUP_ROOT=/root`，并将 `BACKUP_FILE` 设置为先前保存的 `lums-before-restore-....db` 文件的完整名称。然后重新运行“恢复”部分中的同一辅助容器命令。完整性检查成功之前，不要重新启动 LUMS。英文原文：[LUMS database backup restore](../../../server/static/backup-restore.md)。
