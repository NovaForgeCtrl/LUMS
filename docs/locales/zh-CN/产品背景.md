# 产品背景

<!-- impeccable:product-schema 1 -->

## 平台

Web

## 用户

负责集中管理多台 Linux 系统并保持其更新的系统管理员和 IT 团队。产品也应适用于单个管理员、小型 IT 团队以及适当的托管服务环境。

## 产品用途

LUMS 为受管客户端、已安装软件、可用更新和更新作业执行情况提供集中视图。它帮助管理员有针对性地发起工作并验证结果，而不是盲目地在所有系统上应用更新。

## 运行场景

管理员在日常运维中使用 LUMS 检查整个系统集群的健康状态、遥测数据、软件和更新；发起有针对性的更新作业；查看执行历史；并维护用户访问权限、审计记录和数据库备份。基础设施拓扑可以组合已注册的 LUMS 客户端，以及手动维护的系统和关系。

## 能力与限制

- 基于角色和权限的访问控制、审计日志、数据库备份、软件包查看和客户端更新作业是核心运维能力。
- 系统更新操作必须受控、可审计，并如实报告失败；只有在检查通过后，才能表示更新成功。
- 已注册客户端及其上报的数据是可自动导入的基础设施清单数据来源。除非确认未来集成已实现，否则其他基础设施和关系必须明确手动录入。
- 基础设施清单仅限管理员编辑。
- 不得暗示系统能够自动发现任意虚拟机、容器、网络设备或依赖关系。

## 品牌承诺

- 保留 LUMS 名称和现有标志。
- 用户明确将体育场主题称为“LUMS-Stadion”，并要求在系统状态仪表板和实时监控中使用现有体育场背景图。

## 现有依据

- 现有产品界面和主题资源：`server/static/style.css`、`server/static/images/LUMS_Logo.jpg` 和 `server/static/images/lumsstadium.jpg`。
- 已注册客户端、遥测、更新作业、RBAC、审计和备份功能均在 `server/` 包中实现。
- 目前没有经过验证的客户案例、产品基准数据或自动基础设施发现集成。

## 产品原则

- 让管理员掌控系统变更。
- 使运维状态和更新结果可验证。
- 在服务器端执行访问规则，而不只依赖界面。
- 明确区分客户端上报的事实与手动维护的清单数据。
