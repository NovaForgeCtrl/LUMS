# LUMS 健康仪表板

## 目的与范围

经过身份验证的 `/health` 仪表板可让操作人员快速查看所选 LUMS 和设备群的状态：

- 应用程序判定的数据库状态；
- 客户端总数、在线数、未知数和离线数；
- 已启用且安装遥测并有样本的客户端的近期 CPU、内存和网络遥测；
- 警报历史记录和检测到的遥测中断；
- 是否能够检查已配置的备份目录、应用程序识别的最新备份文件，以及审计日志中记录的最近一次成功备份创建时间；
- 配置后显示的可选 Wazuh 和 Suricata systemd 服务状态行。

各客户端详细的主机和网络读数、温度、服务与容器状态、安全事件摘要位于独立的 `/monitoring` 页面。遥测单元以只读方式访问系统 journal，以生成事件摘要；不会发送原始日志消息、用户名或来源地址。若遥测服务账户无法在不获得额外权限的情况下检查运行环境，则无法提供容器详情。这些页面不能证明主机、Docker 守护进程、反向代理、网络或所有受管理客户端均运行正常。列出某个备份也不代表它一定可恢复；请定期在受控环境中执行恢复测试。

## 访问控制

访问 `/health` 页面需要已登录且拥有 `clients.view` 权限的用户。访问仍受应用程序常规身份验证和授权检查的约束。不要绕过登录或反向代理控制来公开仪表板。

独立的 `GET /api/health` 端点会返回轻量级存活响应。响应成功仅表示该路由可以应答，并非对数据库、备份或客户端健康状况的完整评估。

## 客户端状态解释

仪表板根据客户端最后报告的时间戳对客户端进行分类：

| 状态 | 时间戳距今时间 |
| --- | --- |
| Online | 120 秒或更短 |
| Unknown | 超过 120 秒且不超过 600 秒；时间戳缺失／无效；或时间戳位于未来 |
| Offline | 超过 600 秒 |

这些阈值描述的是最近报告时间，并不代表计算机是否已开机或其所有服务是否正常。网络延迟、计算机挂起、代理停止或报告失败都会影响结果。`unknown` 表示信息不足，不应视为故障证明。

## CPU 和内存遥测

遥测是可选功能，与 reporting Agent 和 execution Watcher 分开。如果启用了 systemd timer 且客户端能够连接服务器，遥测服务大约每五秒提交一个样本。

仪表板提供 1 小时、24 小时和 7 天的历史范围，并每五秒刷新设备群遥测。`/monitoring` 上的主机详细数据是最近报告的快照；每个接口的带宽根据连续快照计算。历史查询限制为 1–168 小时，且可能降采样至最多 1,000 个点。新遥测提交处理期间会删除超过七天的样本；如果所有提交都停止，不要假设清理会独立运行。

监控页面的每次 journal 查询最多匹配 500 条记录；显示 `500+` 表示实际数量可能更高。登录／注销历史最多 20 个事件，启动历史最多 10 条。健康仪表板采用固定布局，并使用现有的每用户 CPU／RAM／磁盘阈值（默认值为 90%）。阈值越界和遥测中断根据保留的样本历史推导；服务状态变化和新报告的 SSH 登录失败会记录为带时间戳的事件，最多保留七天。CSV／JSON 导出会提供所选范围内的所有样本；交互式图表最多显示 1,000 个点。

Wazuh 和 Suricata 行为可选项，只报告 systemd 服务状态。必须将相应的已安装单元加入 `LUMS_MONITORED_SERVICES`；LUMS 不会连接 Wazuh 或 Suricata API，也不会导入其警报流。备份运行时间来自审计日志，并非独立的恢复验证。

遥测需要客户端身份验证。远程代理连接必须使用 HTTPS；只有环回地址允许明文 HTTP。如果服务器使用私有证书颁发机构，请配置 CA 文件。设置详情请参阅[遥测指南](遥测.md)和[安装指南](安装与升级.md)。英文原文：[LUMS Health Dashboard](../../../LUMS_Health_Dashboard.md)。

## 备份存储状态

备份部分反映应用程序能否检查已配置的备份目录，以及它识别到的最新备份文件。它不会独立验证每份备份的内容，不会确认是否已复制到主机之外，也不能证明数据库可以成功恢复。

建议的运维流程：

1. 确认显示的备份日期对于恢复目标而言足够新。
2. 检查备份作业和应用程序日志是否存在错误。
3. 确认备份已复制到适当且受保护的目标位置。
4. 定期在单独的受控位置测试恢复。

不要为了排查问题而删除或覆盖正在使用的数据库或备份文件。

## 状态异常时的建议检查

1. 检查 LUMS 容器和近期日志。
2. 如果无法访问页面或 API，请检查反向代理和 TLS 配置。
3. 对于标记为未知／离线的客户端，检查其 reporting Agent 和 Watcher timer 以及近期 journal 条目。
4. 对于缺少遥测的情况，检查 `lums-telemetry.timer`、`lums-telemetry.service` 以及客户端／服务器配置。
5. 对于备份警告，请检查配置的备份路径、文件系统权限、可用空间和近期备份日志。
6. 更改配置之前，记录观察到的状态和时间戳。

诊断命令请参阅[故障排除指南](故障排查.md)，日常维护和备份流程请参阅[管理指南](管理与备份.md)。英文原文：[LUMS Health Dashboard](../../../LUMS_Health_Dashboard.md)。
