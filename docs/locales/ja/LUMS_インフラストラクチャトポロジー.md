# LUMS インフラストラクチャトポロジー

## 目的

認証が必要な `/infrastructure` ページでは、登録済みの LUMS クライアントと手動で管理するインフラストラクチャを、1 つの依存関係ビューにまとめます。これはインベントリと関係性のマップであり、自動ネットワーク検出や構成管理のシステムではありません。

## データソースと管理主体

- 登録済み LUMS クライアントは既存のクライアントレジストリから読み込まれ、報告されたホスト名、IP アドレス、オペレーティングシステム、有効／報告状態とともに自動表示されます。無効なクライアントも、既存の関係性を理解しやすいように表示されます。これらの項目はトポロジーページでは読み取り専用です。通常のクライアント管理手順で管理してください。
- サーバー、仮想マシン、コンテナー、ネットワーク機器、サービス、ストレージは、ホスト名、IP アドレス、役割、場所、メモを指定して手動で登録できます。
- 関係性は手動で管理します。サポートされる種類は `depends on`、`hosts`、`connects to`、`runs on` です。
- このページはサブネットをスキャンしたり、クラウド API を照会したり、サービスやコンテナーの設定から依存関係を推測したりしません。手動で登録したインベントリと関係性は最新に保ってください。

## アクセス制御と監査

`clients.view` 権限を持つユーザーはトポロジーを表示できます。手動項目や関係性の作成、編集、削除は、`infrastructure.manage` 権限を持つ管理者に制限されます。変更には、アプリケーションの通常の認証済みセッション、CSRF 保護、監査ログ記録が適用されます。

`infrastructure.manage` は `users.manage` と `clients.view` に依存し、`016-infrastructure-topology` データベースマイグレーションによって管理者に付与されます。手動管理ノードを削除すると、そのノードの関係レコードも削除されます。クライアントを削除すると、そのクライアントを参照する関係も削除されます。

## マップの読み方

マップはノードをカテゴリ別に配置し、記録された各関係を方向付きエッジで示します。**共有依存先**とは、少なくとも 2 つの他のノードから `depends on` で参照されるノードです。これは潜在的な中心障害点を確認するための有用な手掛かりですが、可用性や影響を完全に分析するものではありません。冗長性、フェイルオーバー、容量、ネットワーク分割、記録されていない依存関係は考慮されません。

正確なホスト名、IP アドレス、役割、場所、関係の詳細は、インベントリと関係性のテーブルを参照してください。トポロジーには現在選択されている LUMS テーマが適用され、共通の折りたたみ式サイドバーに対応します。原文は[英語のインフラストラクチャトポロジーガイド](../../../LUMS_Infrastructure_Topology.md)です。
