# 製品コンテキスト

## プラットフォーム

Web

## ユーザー

複数の Linux システムを一元管理し、最新状態に保つ責任を担うシステム管理者や IT チームを対象とします。単独の管理者、小規模な IT チーム、適切なマネージドサービス環境にも適合する製品を目指します。

## 製品の目的

LUMS は、管理対象クライアント、インストール済みソフトウェア、利用可能な更新、および更新ジョブの実行状況を一元的に表示します。全システムへ無差別に更新を適用するのではなく、管理者が対象を選んで作業を開始し、その結果を確認できるよう支援します。

## 運用環境

管理者は日常業務で LUMS を使用し、システム群の健全性、テレメトリ、ソフトウェア、更新を確認し、対象を絞った更新ジョブを開始し、実行履歴を確認し、ユーザーアクセス、監査記録、データベースバックアップを管理します。インフラストラクチャトポロジーは、登録済み LUMS クライアントと、手動で管理するシステムおよび関係を組み合わせられます。

## 機能と制約

- ロール／権限ベースのアクセス制御、監査ログ、データベースバックアップ、パッケージの可視化、クライアント更新ジョブは、主要な運用機能です。
- システム更新は、制御され、監査可能で、失敗を正確に報告する必要があります。検証に成功していない更新を成功したと示してはいけません。
- 自動インポートされるインフラストラクチャインベントリの情報源は、登録済みクライアントとその報告データです。将来の連携が確認されない限り、追加のインフラストラクチャや関係は明示的に手動登録する必要があります。
- インフラストラクチャインベントリを編集できるのは管理者だけです。
- 任意の VM、コンテナー、ネットワーク機器、依存関係が自動検出されると示してはいけません。

## ブランドに関する方針

- LUMS の名称と既存のロゴを維持します。
- ユーザーはスタジアムテーマを明示的に「LUMS-Stadion」と呼び、システム健全性ダッシュボードとライブ監視に既存のスタジアム背景画像を使用するよう依頼しています。

## 確認済みの情報

- 既存の製品インターフェースとテーマ素材: `server/static/style.css`、`server/static/images/LUMS_Logo.jpg`、`server/static/images/lumsstadium.jpg`。
- 登録済みクライアント、テレメトリ、更新ジョブ、RBAC、監査ログ、バックアップの実装は `server/` パッケージにあります。
- 検証済みの顧客事例、製品ベンチマーク、自動インフラストラクチャ検出連携は提供されていません。

## 製品原則

- システム変更の主導権を管理者が持てるようにします。
- 運用状態と更新結果を検証可能にします。
- アクセスルールは画面だけでなくサーバーで強制します。
- クライアントから報告された事実と手動管理のインベントリを区別します。
