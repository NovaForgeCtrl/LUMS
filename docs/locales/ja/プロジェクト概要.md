# LUMS

**ノイズのない Linux アップデート管理。**

## はじめに

LUMS（Linux Update Management Server）は、Linux クライアントのソフトウェアと更新を一元管理するシステムです。サーバーはクライアント、インストール済みソフトウェア、利用可能な更新を表示します。各管理対象 Linux システム上のエージェントは、そのシステムのパッケージマネージャーを使用して、承認されたパッケージ操作を実行します。LUMS は Debian／Ubuntu の APT や Arch Linux の pacman を置き換えません。

**既存の LUMS を利用するだけの場合:** 管理者から案内されたアドレスを開き、自分専用のアカウントでサインインしてください。機能が表示されない場合、そのアカウントに必要な権限がない可能性があります。アカウントを共有したり、クライアントトークンを Web パスワードとして使ったりせず、管理者に問い合わせてください。

**LUMS をインストールまたは運用する場合:** [インストールガイド](インストールとアップグレード.md)を読み、続いて[管理ガイド](管理とバックアップ.md)を確認してください。問題が発生した場合は[トラブルシューティングガイド](トラブルシューティング.md)を参照してください。ユーザー／管理者向けの翻訳ガイドは各言語のドキュメントにあります。英語のルートガイドが技術的な原本です。翻訳された手順が不完全または異なる場合は、英語の原本に従ってください。

テストの成功や Docker イメージをビルドできたことだけでは、本番環境の導入が完了したことにはなりません。本番環境には HTTPS、保護されたアプリケーションシークレット、永続データ、検証済みバックアップ、強化されたコンテナーが必要です。実行前に、本番コマンド内のプレースホルダーと保存先を自身の環境に合わせて確認してください。

## Web インターフェースの言語

Web インターフェースでは、ドイツ語、英語（米国／英国）、フランス語、スペイン語、中国語（簡体字）、日本語、ポーランド語、スウェーデン語、ノルウェー語（ブークモール）、フィンランド語を選択できます。ログインページ右上で言語を選びます。選択しない場合、LUMS はブラウザーの言語を使用しようとします。サインイン後は、アカウントに保存された言語設定が優先されます。翻訳がない場合、一部の技術用語や動的テキストは元の言語で表示されることがあります。Markdown ガイドは Web インターフェースとは別であり、自動翻訳されません。

## LUMS とは

LUMS は、中央サーバーと軽量な Linux クライアントで構成されます。サーバーは管理インターフェース、API、認証、認可、ジョブ管理、監査ログ、永続状態を提供します。クライアント側エージェントはローカルのパッケージマネージャーを操作し、結果をサーバーに報告します。

```text
                    ┌──────────────────────┐
                    │    Web ブラウザー     │
                    └──────────┬───────────┘
                               │
                               ▼
                    ┌──────────────────────┐
                    │    LUMS サーバー      │
                    │ Web UI / API         │
                    │ 認証・RBAC            │
                    │ ジョブ管理・監査ログ  │
                    │ SQLite               │
                    └──────────┬───────────┘
                               │ HTTPS / API
                 ┌─────────────┴─────────────┐
                 ▼                           ▼
          ┌──────────────┐             ┌──────────────┐
          │ Linux クライアント│             │ Linux クライアント│
          │ LUMS Agent   │             │ LUMS Agent   │
          │ Package Mgr  │             │ Package Mgr  │
          │ Watcher      │             │ Watcher      │
          └──────────────┘             └──────────────┘
```

管理サーバーは処理の調整とポリシーを担い、クライアントはローカルシステムとのやり取りを担います。実際のインストール、削除、更新は引き続き各 OS のパッケージマネージャーが実行します。目的は Linux の仕組みを隠すことではなく、操作を一元的に管理し、追跡可能にすることです。

## 主な機能

### クライアントとインベントリ

各クライアントには個別の認証トークンがあります。サーバーはトークンを平文で保存せず、SHA-256 ダイジェストを保存して受信した認証情報を検証します。管理者はクライアントを登録／無効化し、トークンをローテーションし、状態や報告状況を確認できます。

クライアントはインストール済みソフトウェアと利用可能な更新を報告します。インストール済みソフトウェアの表示とパッケージ検索は別々です。これにより、読み取り専用の利用者がパッケージ操作に自動的にアクセスすることなく、インベントリを確認できます。

### パッケージ操作と更新ジョブ

サポートされる操作は `INSTALL_PACKAGE`、`REMOVE_PACKAGE`、`UPDATE_PACKAGE`、`UPDATE_SYSTEM` です。対応するパッケージ管理系統は次のとおりです。

* **Debian / Ubuntu:** APT / dpkg
* **Arch Linux:** pacman

パッケージ検索要求は対象クライアントに送られ、そのローカルパッケージマネージャーで実行されてから結果がサーバーに返されます。

更新操作は永続ジョブとして管理されます。ジョブには複数のパッケージ操作を含められ、サーバー側で実行状態を追跡します。パッケージ単位の結果は個別に記録されるため、途中で中断しても成功済みの操作を不必要に繰り返さずに復旧できます。Web UI から任意のシェルコマンドを実行することはできません。サーバーは検証済みアクションとパッケージ名を使用して構造化されたジョブを作成し、エージェントがローカルのパッケージマネージャー操作に対応付けます。

クライアントがアクティブと判断された場合、更新実行を延期できます。現在のアイドルしきい値は **300 秒**です。対応環境では `loginctl` を使用してセッション／アイドル状態を取得します。検出できない場合、アイドル状態を確認済みとは扱いません。状態不明はアイドル確認済みとは異なります。

一部のパッケージ操作では再起動が必要になる場合があります。パッケージマネージャーが成功コードを返しただけでシステム全体が正常とはみなさず、クライアントが検出した再起動要否をサーバーへ報告します。

### ヘルスと監査

認証済み `/health` ダッシュボードは、データベース状態、クライアント報告状態、バックアップストレージの可視性、設定されている場合の CPU／メモリテレメトリを要約します。これは運用状況の簡易表示であり、コンテナー、リバースプロキシ、ホスト、バックアップのログ確認や復元テストの代わりにはなりません。レイアウトは固定で、表示項目のカスタマイズモードはありません。詳細は[LUMS ヘルスダッシュボード](LUMS_システム健全性ダッシュボード.md)を参照してください。

管理操作およびセキュリティ関連操作は監査ログに記録されます。監査記録は「誰が、何を、いつ、どの対象に対して行い、どの結果になったか」を確認できるようにします。

## ロールとアクセス制御

標準の権限テンプレートは次の 3 つです。

* **Administrator:** ユーザーとクライアントの管理を含む管理者機能。
* **Operator:** 日常的な更新・運用管理。
* **Viewer:** 読み取り専用のクライアント／ソフトウェア表示。

ロールは既定の権限セットを提供します。実際のアクセスはアカウントに保存された権限によってサーバー側で判定されます。画面上のボタンを隠すだけではセキュリティ境界になりません。API も権限を検証します。

## セキュリティの基本

LUMS は、Web ユーザーの認証とクライアント認証を分離します。Web ユーザーはアカウントとパスワードでサインインし、クライアントは個別のトークンで API に接続します。パスワードは Argon2 でハッシュ化され、クライアントトークンはサーバー側で SHA-256 ダイジェストとして管理されます。ログイン試行のレート制限、セッション無効化、CSRF 保護、入力検証、監査記録を適用します。

本番環境では、HTTPS、保護されたシークレット、永続 Docker ボリューム、読み取り専用ルートファイルシステム、root 以外のアプリケーションユーザー、Linux capability の削除、`no-new-privileges`、localhost のみへのアプリケーションポート公開を維持してください。LUMS サーバーを直接ネットワークへ公開せず、HTTPS リバースプロキシを使用します。

ジョブ復旧では、ジョブ全体を盲目的に最初からやり直すのではなく、成功済みのパッケージ項目を保ちます。アプリケーションデータベースは SQLite で、WAL モード、`busy_timeout = 5000`、`synchronous = 2`、`foreign_keys = ON` を使用します。

## 対応環境と技術

サーバーは Docker 上の Flask／Gunicorn Web アプリケーションと SQLite を使用し、Nginx が外部 HTTPS 接続を受け付けます。管理対象 Linux クライアントでは Python 3、systemd、対応パッケージマネージャー、サーバーへのネットワーク接続、有効なクライアントトークン、信頼できる TLS 証明書が必要です。
