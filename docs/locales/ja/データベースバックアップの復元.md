# LUMS データベースバックアップの復元

このガイドでは、Docker デプロイメントで `.db` または `.db.gz` バックアップを復元します。復元するとアクティブなデータベースが置き換わります。慎重に作業し、Debian ホスト上で手順を実行してください。

## 前提条件

次の情報が必要です。

* バックアップストレージのホストパス（例: `/mnt/lums-nas-backups`）
* 使用している場合は、LUMS バックアップ画面で選択したサブフォルダー
* バックアップファイル名
* データベースボリューム名（通常は `lums-data`）
* 1 回限りの復元コンテナーで使用する LUMS イメージ

稼働中のインストールと同じイメージバージョンを使用してください。設定済みイメージ名は次のコマンドで確認できます。

```bash
sudo docker inspect lums --format '{{.Config.Image}}'
```

以下の `lums:SET-TO-ACTIVE-IMAGE-TAG` を、確認したイメージ名に正確に置き換えてください。ホストに残っているという理由だけで古いイメージタグを使用しないでください。

NAS／ファイルシステムのマウントが利用可能である必要があります。復元前に確認してください。

```bash
mountpoint /mnt/lums-nas-backups
ls -lh /mnt/lums-nas-backups
```

`/mnt/lums-nas-backups` は実際のホストパスに合わせて変更してください。LUMS に表示されるのはコンテナ内のパスです。Docker マウントの左側がホストパスです。

## 復元

インストールに合わせて変数を設定します。`BACKUP_FILE` はバックアップマウント内のファイル名を指定してください。UI のサブフォルダーを使う場合は、例の `wochenende/lums-backup-....db.gz` のようにパスに含めます。

```bash
BACKUP_ROOT=/mnt/lums-nas-backups
BACKUP_FILE=lums-backup-DATEINAME.db.gz
LUMS_VOLUME=lums-data
LUMS_IMAGE=lums:SET-TO-ACTIVE-IMAGE-TAG
```

LUMS を停止し、追加の復旧手段として現在のデータベースを保存します。

```bash
sudo docker stop lums
sudo docker cp lums:/var/lib/lums/lums.db \
  "/root/lums-before-restore-$(date +%F-%H%M%S).db"
```

1 回限りの補助コンテナーを使って選択したバックアップを復元します。スクリプトは置き換え前にデータベースの整合性を確認し、ファイル所有者を LUMS 実行ユーザーに戻します。

```bash
sudo docker run --rm \
  --user 0:0 \
  --entrypoint python \
  -v "$LUMS_VOLUME:/var/lib/lums" \
  -v "$BACKUP_ROOT:/backups:ro" \
  "$LUMS_IMAGE" \
  -c '
import gzip
import os
import shutil
import sqlite3
import sys
import tempfile

source_path = sys.argv[1]
database_path = "/var/lib/lums/lums.db"
fd, temporary_path = tempfile.mkstemp(
    prefix=".lums-restore-",
    suffix=".db",
    dir="/var/lib/lums",
)
os.close(fd)
try:
    opener = gzip.open if source_path.endswith(".gz") else open
    with opener(source_path, "rb") as source, open(temporary_path, "wb") as target:
        shutil.copyfileobj(source, target)

    database = sqlite3.connect(temporary_path)
    try:
        result = database.execute("PRAGMA integrity_check").fetchone()
    finally:
        database.close()
    if result is None or result[0] != "ok":
        raise RuntimeError("Backup failed SQLite integrity_check")

    for suffix in ("-wal", "-shm"):
        sidecar = database_path + suffix
        if os.path.exists(sidecar):
            os.unlink(sidecar)
    os.chmod(temporary_path, 0o600)
    os.chown(temporary_path, 10001, 10001)
    os.replace(temporary_path, database_path)
    print("Backup restored and integrity_check passed.")
finally:
    if os.path.exists(temporary_path):
        os.unlink(temporary_path)
' "/backups/$BACKUP_FILE"
```

LUMS を再起動し、マイグレーションとサービスを確認します。

```bash
sudo docker start lums
sudo docker logs --tail 100 lums
curl -s -o /dev/null -w 'GET /login: %{http_code}\n' \
  http://127.0.0.1:5050/login
```

その後、サインイン、ユーザー、クライアント、ジョブを確認してください。復元したバックアップが現在のアプリケーションより古い場合、起動時に LUMS がデータベースマイグレーションを実行することがあります。

## 復元に失敗した場合

破損したデータベースを本番環境の状態として使い続けないでください。LUMS をもう一度停止します。`BACKUP_ROOT=/root` とし、`BACKUP_FILE` には事前に保存した `lums-before-restore-....db` ファイルの完全な名前を指定してください。その後、「復元」セクションと同じ補助コンテナーコマンドを再実行します。整合性チェックに成功するまで LUMS を再起動しないでください。原文は[英語のデータベースバックアップ復元ガイド](../../../server/static/backup-restore.md)です。
